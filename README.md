# CSonEmbedding — 轻量级 LLM 前置安全过滤器

**一个放在 LLM 推理之前的小型恶意/越狱输入检测器。** 把句向量(冻结的 BGE 编码器)送进一个极小的判别头,在毫秒级判断"这条输入是攻击还是正常",无需调用任何大模型。核心目标:**既抓得住越狱攻击,又不冤枉"听着像攻击其实正常"的请求(过度拒绝)**。

> ⚠️ **方向更新(v13/v14, 2026-06)**:经过一轮系统的受控实验,本项目最初的"压缩感知(CS)"理论框架**已被我们自己的实验推翻**(见 §4)。真正起作用、且最新最强的做法是 **判别式决策头 + (可选)低维压缩**。本 README 已据此诚实重写;早期 CS/v9 叙述仅作历史保留。

---

## 最新发现(v13/v14):过度拒绝主要是"决策规则"问题,不是"表示"问题

我们一度以为前置过滤器误拦正常请求(如"how do I **kill** a Python process?")是编码器表示的固有缺陷。一轮受控实验(投影/margin/编码器微调全部无效或退化)后,**编码器能力扫描**揭示了真相:

- **XSTest(过度拒绝标准基准)在任何编码器上,有害 vs 边界正常的判别 AUC ≈ 0.999** —— 分开它们的方向**本来就存在**,只是 v9 的"双质心余弦"决策没用上它。
- **真正的修复 = 把双质心余弦换成判别头(logistic),并在多样攻击 + 边界数据上训练。**

**受控对比(同训练数据、同评测口径、阈值锁攻击 DR≥0.90;留出 JBB/XSTest 与各攻击 30% 作评测):**

| 编码器 | 决策 | 攻击DR↑ | JBB 误拦↓ | XSTest 误拦↓ |
|---|---|---:|---:|---:|
| BGE-base | 双质心(几何, =旧 v9 思路) | 0.889 | 0.70 | 0.773 |
| **BGE-base** | **判别头(logistic)** | **0.957** | **0.367** | **0.133** |
| E5-large | 双质心 | 0.843 | 0.50 | 0.227 |
| **E5-large** | **判别头(logistic)** | 0.881 | **0.20** | **0.0** |

> **同一套设置下,只把"几何决策"换成"判别头",过度拒绝大幅下降、攻击检测不降反升** —— 这是无代价的严格改进,且不需要换编码器。换 E5-large 还能进一步把边界误拦压到近零。
> (注:此处"双质心"为该受控设置下的简化版,数值不同于历史 §3 中带边界训练的部署版 v9;此对比用于**隔离决策规则这一个变量**。)

### 压缩仍然保留(v14):又小、又不冤枉好人、还抓得准

在判别头前做压缩,结论:

| 压缩 | 维度 | 攻击DR | JBB 误拦 | XSTest 误拦 |
|---|---:|---:|---:|---:|
| 不压缩 | 768 | 0.957 | 0.367 | 0.133 |
| 随机投影 | 256 | 0.958 | 0.367 | 0.147 |
| 随机投影 | 32 | 0.897 | 0.567 | 0.32 |
| **PCA** | **32** | **0.868** | **0.267** | **0.053** |

- **随机压到 256 维 ≈ 零损失**(3× 压缩白送)。
- **PCA 压到 32 维(24× 压缩)** → 过度拒绝几乎消除(XSTest 误拦 5%、JBB 27%),攻击 DR 仍 0.87。**一个又小又强的检测头。**
- 有意思:在 **32 维这种极限压缩下,结构化压缩(PCA)明显优于随机**(JBB 0.27 vs 0.57)——压得越狠,"学习型压缩"越有价值(温和压缩下二者相当)。

**三赢**:压缩(小/省) + 判别头(修过度拒绝) + 防御不降。

## 方法

```
文本 → 冻结 BGE 编码器(768D mean-pool) → [可选] 低维压缩(PCA-32 / 随机) → 判别头(logistic) → 攻击/正常
```

- **编码器**:`BAAI/bge-base-en-v1.5`(v7 微调,冻结);可选换 `intfloat/e5-large-v2`(边界更好)。
- **压缩(可选)**:PCA 或随机正交投影到 32–256 维。低维带来去噪/正则与极小存储/比对开销。
- **决策头**:在**多样攻击(AdvBench/HarmBench/GCG/PAIR/JailbreakHub)+ 正常 + 边界(OR-Bench/XSTest/JBB-Benign)**上训练的判别式分类器(logistic)。这是修复过度拒绝的关键。
- 推理无需 LLM;延迟主要在编码器(~13ms 单条 / <1ms 批量),决策头开销可忽略。

## Youden's J:为什么"低假阳"必须和检测率一起看

**单看假阳率低毫无意义**——"永远判正常"的分类器假阳=0,检测率也=0。用 **Youden's J = 检测率 − 假阳率** 才能看真本事:一个靠"欠检测"刷低假阳的方法(如某些注入检测器把 AdvBench 全判安全 → DR=0)J 接近 0;本方法的低假阳是**伴随高检测**的真区分能力。详见 [`results/baselines/S2_REPORT.md`](results/baselines/S2_REPORT.md)。

## 诚实的局限与被推翻的假设

- **CS(压缩感知)理论被自己的实验推翻**:6 个受控实验(`results/v9_boundary/PREMISE_ANALYSIS.md`)证明安全信号在 embedding 中是**稠密**而非稀疏的;压缩有效是"降维去噪 + 稠密冗余"(JL),**不是** CS 的稀疏恢复。"低维分布"这一前提属于已有的 refusal-direction 文献,非本项目发现。
- **边界 margin(早期 v9 的 A2)在受控对比中收益甚微**:同数据上有/无 margin 差别不大,且不跨边界分布迁移。早期 v8→v9 的改善主要来自**边界数据扩充**,不是 margin 机制。
- **编码器微调失败**:顶层微调(含锚点防遗忘)都会牺牲对未见攻击类型的泛化(攻击 DR 0.79→0.47–0.59),不可取。
- **v13/v14 为最新结果,评测集偏小**(留出 JBB 30 / XSTest 75 / 各攻击 24–60),**待补随机种子确认**;PAIR 是最弱攻击类型(E5+判别头上 DR 0.65)。
- 最强的 LLM 护栏(LlamaGuard/WildGuard/PromptGuard 等)为 HF 门控,未头对头自测,见 S2 报告。

## 项目结构与复现

| 路径 | 内容 |
|---|---|
| `scripts/v9_boundary/encoder_sweep.py` | 编码器能力扫描(揭示过度拒绝是决策规则问题) |
| `scripts/v9_boundary/v13_eval.py` | **v13**:编码器 × 决策(双质心/判别头)2×2 消融 |
| `scripts/v9_boundary/v14_compress.py` | **v14**:压缩 × 判别头,小模型保留修复 |
| `scripts/v9_boundary/PREMISE*/margin_datatest/v11_*` | CS 前提审查、margin 测试、编码器微调(均为负结果) |
| `results/v9_boundary/*.json` + `PREMISE_ANALYSIS.md` | 上述实验的结果与判读 |
| `scripts/baselines/` + `results/baselines/` | 统一协议基线对比 + Youden's J 分析 |
| `scripts/v8_cs_supcon/`, `results/.../S1_REPORT.md` | 历史 v8/v9(CS 框架,已被后续推翻) |

**权重**:编码器 `models/v7_classifier/best_model.pt` 在 [HuggingFace](https://huggingface.co/ludandaye/embedding-prefilter);判别头/压缩需在 GPU 上按 `scripts/v9_boundary/v13_eval.py` / `v14_compress.py` 重训(很快)。
